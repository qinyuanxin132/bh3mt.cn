# CTF Reverse 个性化学习档案 & AI 交接中心

本目录用于集中维护 **CTF Reverse（逆向工程）** 的个人学习画像、整体路线大纲、实时进度与复盘日志。
放在 `blog-site/docs/re-learning/` 下，**不会被 Astro 打包为公开博客文章**，但与 `src/content/posts/` 下的博客笔记和 WP 同库共存，方便随时查阅与对照。

---

## 目录导航

| 文件 | 作用 | 更新频率 |
|---|---|---|
| [PROFILE.md](./PROFILE.md) | 能力画像、已学知识盘点、真实掌握度评估、高频踩坑备忘录 | 每完成一次测验或阶段复盘 |
| [ROADMAP.md](./ROADMAP.md) | CTF Reverse 整体知识大纲 & 4 阶段个性化学习路线（含验收标准） | 每完成一个阶段或方向调整 |
| [PROGRESS.md](./PROGRESS.md) | **防跑偏看板**：当前阶段焦点、正在刷的题目队列、下一步具体行动 | 每次学习/对话结束 |
| [LOG.md](./LOG.md) | 按时间线记录的测验、刷题、复盘与突破日志 | 每次重要练习后追加 |

## 给任何接手本项目的 AI 助手的协议（Handoff Protocol）

如果你是新开启的会话或其他 AI 模型，请按以下步骤快速接手，避免重复摸底或跑偏：

1. **必读顺序**（约 30 秒完成上下文恢复）：
   - 先读 [PROGRESS.md](./PROGRESS.md)：明确**当前正在做什么**和**下一题/下一步**。
   - 再读 [PROFILE.md](./PROFILE.md)：了解学习者当前的真实水平、核心短板和常踩的坑。
   - 需要规划新阶段或查大纲时，再读 [ROADMAP.md](./ROADMAP.md) 和 `src/content/posts/` 下对应的历史笔记。
2. **核心前提**：
   - **“博客写过笔记 ≠ 真正掌握”**。博客里的 WP 和笔记只代表“接触过”，是否掌握必须以**无提示独立实战 / 摸底检验**为准。
   - 路线图状态标记约定：
     - `[ ]` 未接触
     - `[~]` 已接触/写过笔记，但尚未独立验收
     - `[x]` 已通过独立实战或测验，真正掌握
3. **辅导与交互风格**：
   - **阶梯式提示，不直接剧透**：做题时先让学习者给自己的分析思路；卡壳时先给方向提示，再给局部提示，不直接甩完整解密脚本或最终 flag。
   - **刻意补短板**：在当前阶段，引导学习者养成“读汇编先写寄存器角色表”、“纯 Python 写位宽截断”、“每题至少用 `pwndbg` 动手调试验证一次”的习惯。
   - **保持聚焦**：紧扣 `PROGRESS.md` 的当前主线，不要轻易铺开过多新坑。
4. **收尾更新**：
   - 每次完成一道题、一次小测或一次阶段讨论后，主动更新 [PROGRESS.md](./PROGRESS.md) 的状态与 [LOG.md](./LOG.md) 的记录；若某项能力从 `[~]` 跃迁到 `[x]`，同步更新 [PROFILE.md](./PROFILE.md) 和 [ROADMAP.md](./ROADMAP.md)。
