# 汇编与 CTF Reverse 学习周记：从看不懂汇编到第一次解出 ELF

最近一周主要在学习 x86-64 汇编和 CTF Reverse。

之前虽然接触过一些 C 语言、指针和内存相关的知识，但真正面对反汇编代码时，还是会有一种不知道从哪里开始看的感觉。寄存器、内存地址、条件跳转、栈帧混在一起，单独看某条指令或许还能理解，连起来就比较困难了。

这周主要跟着学习路线做了一些专项练习，后面逐渐开始分析真实的 GCC 编译结果，还尝试逆向了一道没有源码的 Linux ELF。

记录一下这段时间学过的东西和遇到的问题，也方便以后回头复习。

## 一、从寄存器和函数栈帧开始

最开始学习的是 x86-64 的基础寄存器、函数调用和栈结构。

比较常见的寄存器有：

| 寄存器 | 作用 |
|---|---|
| RAX/EAX | 常用于保存返回值 |
| RDI/EDI | 第一个整数或指针参数 |
| RSI/ESI | 第二个整数或指针参数 |
| RDX/EDX | 第三个参数，也经常作为临时寄存器 |
| RSP | 栈顶指针 |
| RBP | 常用的栈帧基址 |
| RIP | 下一条要执行的指令地址 |

这里的参数传递规则主要针对 Linux x86-64 System V ABI。

刚开始的时候，我对下面两条指令还不太熟悉：

```asm
push rbp
mov rbp, rsp
```

后来才逐渐理解，它们通常用于保存调用者的 RBP，并建立当前函数的栈帧。

函数结束时常见的：

```asm
leave
ret
```

则负责恢复栈帧并返回调用者。

其中比较有收获的一次练习，是使用 GDB 实际跟踪 `CALL` 和 `RET`。

之前只知道 `CALL` 会调用函数，`RET` 会返回。但单步调试后发现：

- `CALL` 会把返回地址压入栈中。
- 在 64 位模式下，压入一个返回地址通常使 RSP 减少 8。
- `RET` 会从栈中取出返回地址，并恢复 RIP。

当时通过 pwndbg 观察 RSP、RIP 和栈顶内存的变化，才真正把这些概念联系起来。

这部分给我的感受是：**汇编只看文字说明还是比较抽象，实际单步执行一次会直观很多。**

## 二、条件跳转与循环

接下来主要学习了 CMP、TEST 和条件跳转。

一开始容易混淆的就是这些指令：

```asm
je
jne
jg
jge
jl
jle
ja
jb
```

后来逐渐理清了有符号比较和无符号比较的区别。

例如：

```asm
cmp eax, ecx
jg somewhere
```

`JG` 是有符号大于，而 `JA` 是无符号大于。

对于 `0xFFFFFFFF` 这样的数据，如果按有符号 32 位整数解释，它是 -1；如果按无符号整数解释，它就是 4294967295。

因此同样两个寄存器的值，使用 `JG` 和 `JA`，跳转结果可能完全不同。

另外还学习了：

```asm
test eax, 1
```

通过按位与判断整数的最低位，从而确定奇偶性。

在理解这些条件跳转后，开始进行汇编与 C 语言的双向转换练习。

例如将：

```c
int sum_positive(int *a, int n)
{
    int sum = 0;

    for (int i = 0; i < n; i++)
    {
        if (a[i] > 0)
            sum += a[i];
    }

    return sum;
}
```

转换为汇编。

第一次自己完整写出数组遍历函数时，还是挺有成就感的。

其中数组寻址：

```asm
mov edx, DWORD PTR [rdi+rcx*4]
```

对应的就是：

```c
edx = a[i];
```

因为 `int` 占 4 字节，所以数组下标需要乘以 4。

这一阶段最大的变化是，看到一段汇编后，已经能逐渐想到对应的 `if`、`for` 和数组操作，而不是只认识单条指令。

## 三、开始接触 GCC 优化后的汇编

之前分析的大部分程序都是 `-O0` 编译的。

到了后面，开始尝试使用自己电脑上的 GCC 16.2.1，将同一段 C 代码分别编译为 `-O0` 和 `-O2` 汇编。

使用的命令类似：

```bash
gcc -O0 -S -masm=intel optimize.c -o optimize_O0.s

gcc -O2 -S -masm=intel optimize.c -o optimize_O2.s
```

对比之后，发现两者差别确实很大。

`-O0` 经常会保留栈帧，通过 `[rbp-offset]` 访问局部变量，代码结构也比较接近原始 C 语言。

而 `-O2` 往往直接使用寄存器，甚至把条件跳转改成条件赋值。

例如：

```asm
lea eax, [rdi+rdi*2]
lea edx, [rax+5]
sub eax, 7
cmp edi, 11
cmovge eax, edx
ret
```

这里 GCC 先计算出两种可能的结果：

```c
a = x * 3 - 7;
b = x * 3 + 5;
```

然后通过 `CMOVGE` 根据条件选择返回值。

这让我意识到，**逆向不能只按照固定的指令模板去寻找 C 代码，应该重点追踪寄存器保存的数据和整个函数的逻辑。**

后来又学习了 `SETcc`、`CMOVS` 和优化后的数组循环。

例如：

```asm
mov eax, DWORD PTR [rdi]
xor ecx, ecx
test eax, eax
cmovs eax, ecx
add rdi, 4
add edx, eax
```

这里 GCC 不再使用 `i++` 这种下标变量，而是直接让数组指针前进 4 字节。

如果读取到负数，就通过 `CMOVS` 将其变为 0，再参与累加。

这一部分刚开始有些不习惯，不过在自己写注释、逐轮模拟寄存器变化之后，慢慢能看懂了。

## 四、第一次完整逆向 ELF

前面的学习大部分还是针对单个函数进行分析。

后来感觉继续做简单的汇编翻译题有些重复，于是决定尝试一道没有源码的 ELF。

这道题是 Linux x86-64 程序，符号表已经剥离。

先通过 IDA 找到了 `main` 函数，核心逻辑大致是：

```c
if (argc == 2)
{
    if (sub_401200(argv[1]))
    {
        puts("Access granted.");
        return 0;
    }

    puts("Access denied.");
    return 1;
}
```

一开始还疑惑为什么程序没有专门的输入函数，后来才反应过来，它是通过命令行参数 `argv[1]` 获取输入的。

随后进入校验函数，发现程序会对输入字符串逐字节进行变换。

其中最关键的代码是：

```c
v5 = (unsigned __int8)(
    v3 + (byte_402060[v4] ^ a1[v4])
);

if (byte_402050[v4] !=
    ((unsigned __int8)(2 * v5) |
     (unsigned __int8)(v5 >> 7)))
{
    // 校验失败
}
```

当时我已经知道 XOR 和 ADD 应该逆过来计算，于是写了第一个 Python 脚本。

但是最开始的逆推公式是错的：

```python
a[i] = c[i] / 2 - ((11 + 3*i) ^ b[i])
```

运行之后出现了小数，明显不符合预期。

我当时的疑问是：既然正向能乘以 2，为什么逆向除以 2 会出现小数？

后来才弄明白，原来的：

```c
((unsigned char)(2 * v5)) |
((unsigned char)(v5 >> 7))
```

并不是普通的乘法，而是在实现 **8 位循环左移一位（ROL8）**。

它相当于：

```python
rol = ((x << 1) | (x >> 7)) & 0xff
```

因此逆向应该使用循环右移：

```python
ror = (x >> 1) | ((x & 1) << 7)
```

除此之外，还需要注意逆运算顺序。

正向是：

```text
输入字符
   ↓
XOR 密钥
   ↓
ADD 动态常量
   ↓
ROL8
   ↓
目标字节
```

逆向就应该按相反顺序处理。

最后整理出的核心逆运算是：

```python
v5 = (c[i] >> 1) | ((c[i] & 1) << 7)

a[i] = ((v5 - (11 + 3*i)) & 0xff) ^ b[i]
```

其中 `& 0xff` 用于模拟 8 位无符号整数截断。

运行脚本后，成功恢复出了字符串：

```text
cyb3r_R3v!
```

最后在 Arch Linux 中执行：

```bash
./challenge 'cyb3r_R3v!'
echo $?
```

得到：

```text
Access granted.
0
```

至此，第一道完整 ELF 逆向实战终于成功了。

虽然这道题在 ROL/ROR 的识别和逆运算上接受过提示，不能算完全独立完成，但从定位函数、提取数据，到自己写 Solve、修正错误并实际验证，整个流程还是很有收获的。

## 五、Python 逆向脚本的一些经验

这几天还专门练习了不同移位次数的字符串逆向。

一开始的问题是没有处理好 8 位截断。

例如：

```python
v = v - 3*i - 7
```

在 Python 中，结果可能是负数。

但如果原程序使用的是 `unsigned char`，就需要考虑模 256 的行为：

```python
v = (v - 3*i - 7) & 0xff
```

这次踩坑让我认识到，Python 的整数运算和 C 语言固定宽度整数运算并不完全相同。

以后写逆向脚本时，需要特别注意：

- 正向算法的运算顺序；
- 每一步的数据位宽；
- 有无整数截断或溢出；
- 循环移位和普通移位的区别；
- 最终结果是否能够通过正向算法验证。

另外，以后不能只看 Python 输出了一个看起来像密码的字符串，就认为自己解对了。最好还是把它代入原程序，确认确实能通过校验。

## 六、目前还不熟练的地方

虽然这一周进步不少，但距离真正能够独立做中高难度 CTF Reverse 题目，还有挺大差距。

目前比较明显的问题有：

**1. 汇编语法还不够熟练。**

之前自己写汇编时，出现过 `LEA` 使用不合法比例因子、标签名称不一致等问题。

虽然大致知道程序逻辑，但真正把它写成可汇编代码时，细节还是容易出错。

**2. 遇到陌生算法时，容易只盯着某条指令。**

第一次遇到 ROL8 时就是这样，只注意到了乘以 2，却没有意识到后面的 OR 是整个变换的重要部分。

以后需要更关注完整的数据流。

**3. GDB 还需要更多真实调试经验。**

目前已经会使用断点、单步、查看寄存器和内存，但多数时候还是依赖 IDA 反编译来理解整体逻辑。

遇到更复杂的程序时，应该提高动态分析能力。

**4. Python 自动化能力需要继续加强。**

现在能写简单的字节逆推脚本，但还没有系统学习 Z3、符号执行和常见加密算法的自动化求解。

这些都需要后面结合实际题目慢慢补充。
